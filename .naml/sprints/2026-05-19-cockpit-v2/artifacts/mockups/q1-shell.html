Question 01 / Shell & Information Architecture

How should the cockpit shell be laid out?

The shell is the persistent frame that wraps every view. It decides what telemetry stays in your peripheral vision vs. what you have to navigate to. The three layouts below trade visibility for screen real-estate differently.
← all questions
RECOMMENDATION
Option A — Header + Main + always-on Right Rail. The cockpit feels alive because activity ticker and account quotas never disappear. You're never one tab-switch away from knowing if your weekly quota is about to die or whether a slice just transitioned to review. The 280px price is worth it on a cockpit; flicker-free telemetry is the whole brand.
RECOMMENDED
OPTION A

Header + Main + always-on Right Rail

▟ naml inpolicy/web ▾ Dash Sprint Settings ⚙
HEADER · identity + sync
RIGHT RAIL · telemetry

Header carries identity + sync dot + project switcher + active sprint pin. Main pane swaps between Dashboard / Sprint / Settings via header tabs. Right rail is permanent: live activity ticker on top, CodexBar-style quota bars below (Session %, Weekly %, Today $). Right rail collapses with ⌘\ when you need width.

WINS
  • Telemetry never disappears
  • Quota deaths can't ambush you
  • "Synced 2s ago" always visible
  • 1:1 with 3 state machines
COSTS
  • ~280px permanent loss
  • Wide DAG views feel tight on 13"
  • Two scroll regions on small screens
OPTION B

Header + Main · rail collapsed by default

▟ naml inpolicy/web ▾ $4.21 71% · 84% Dash Sprint ⚙
QUOTAS COMPRESSED IN HEADER
RAIL · 18px strip

Quotas compress into small pill chips in the header itself (71% · 84% · $4.21). Activity ticker is hidden behind a flyout (⌘K or hover the strip). Wide main pane wins for DAG visualization and slice grids on smaller laptops.

WINS
  • Full-width DAG / lane grids
  • Cleaner, calmer surface
  • Better on 13" laptops
COSTS
  • Activity feels "hidden"
  • Quota pills crowd the header
  • Less cockpit, more web app
OPTION C

Left sidebar nav + Main · no rail

▟ naml inpolicy/web ▾ ⚙
SIDEBAR · projects + sprints + inbox

Classic web-app shape. Left rail lists projects, then sprints under the active project, then the feedback inbox. Main pane handles dashboard / sprint / settings. No right rail at all — quotas live inside the Dashboard view.

WINS
  • Sprint history is one click
  • Feedback inbox always visible
  • Familiar — feels like Linear/GitHub
COSTS
  • Quotas hidden in a sub-view
  • Telemetry not in peripheral vision
  • Feels like a CRUD app, not a cockpit
