Question 03 / Dashboard

What should the Dashboard show, and in what order?

The Dashboard is the project-level view — the answer to "what's happening with this codebase right now?". It has to surface project state, the active sprint, queued sprints, feedback inbox, and account-level rollups without becoming a wall.
← all ← Q2
RECOMMENDATION
Option A — Hero card + sprint timeline + feedback inbox sidecar. Project state pulse goes top (state pill + tokens + cost + Tier-1 hit-rate + mean sprint duration). Then a vertical timeline grouped Active / Queued / Recent. Feedback inbox lives as a right sidecar so unaddressed complaints never get hidden behind a tab. This mirrors how your eye scans an aviation HUD — primary status first, then ordered events, with peripheral indicators.

  • Sidecar narrows on small monitors
  • Lineage relationships shown only via label, not visually
